# Audit Report -- Security -- CLI Status and Next Steps

**Date:** 2026-08-22
**Spec version:** v0.1
**Auditor:** Claude (spec mode)

## Scope

Files examined:

- `_index.md` -- Decision Log (D-1 through D-17), Open Questions
- `guiding-principles.md` -- P-1 through P-6
- `out-of-scope.md` -- Excluded items
- `threat-model.md` -- STRIDE analysis and mitigations table
- `config-dir.md` -- Config directory strategy
- `shared-cli.md` -- shared-cli package design
- `sdk-xdg.md` -- SDK XDG support (T5)
- `violations-migration.md` -- violations-framework esbuild + UpdateManager (T4)
- `wdrive-migration.md` -- wdrive npm migration (T7-T9)

## Executive Summary

The threat model is structurally sound for the core distribution pipeline but contains one fictitious mitigation reference ("PyPI probe" for a GitLab npm token), a direct contradiction between D-3 and D-9 about where shared-cli lives (affecting attack surface analysis), and an unanalyzed security regression introduced by D-13 (dropping Ed25519 for wdrive). Several new attack surfaces opened by D-6, D-15, D-17, and T8 UpdateCmd design have no STRIDE coverage. Seven findings are HIGH or CRITICAL and must be resolved before implementation.

## New open questions raised

1. **SEC-01** -- What is the actual GitLab npm WRITE token validation mechanism in CI? The "PyPI probe" reference must be replaced with the real mechanism or T-01 changed to Open.
2. **SEC-02** -- Is shared-cli in the agent-fleet monorepo or at github.com/Wadeck/shared-cli? The answer changes T-06 attack surface analysis entirely.
3. **SEC-03** -- What compensating control replaces Ed25519 for wdrive binary integrity post-D-13? Options: npm package provenance, 2FA on CI token, hash pinning in wdrive consumers.
4. **SEC-04** -- Should `launcher.config.json` be made read-only post-install? npm global installs leave files writable by default; this may require a post-install script.
5. **SEC-05** -- Should consumers pin `@wadeck/shared-cli` to exact CalVer (no `^`) until T-06 is resolved?
6. **SEC-08** -- Should scraper auto-update be disabled given schtasks.exe OS persistence capabilities? Full UpdateManager adoption (D-15) may be too broad for tools with OS persistence access.
7. **SEC-09** -- What permissions are set on `~/.npmrc` and newly created config dirs on Windows? The spec does not specify.

# Spec: Worker Availability CLI

**Created:** 2026-09-11
**Version:** v0.2
**Status:** v0.5 -- 66 decisions, **no open questions**. Q#30 and Q#37 resolved by D#65/D#66; Q#38 closed as not worth solving. Plan at `.claude/plans/2026-09-12_worker-availability-cli.md`, ready to execute from Phase 0.
**Iteration:** 2

## Summary

Decouples worker creation from the flow engine. Today the flow daemon forks every worker itself as a local child process. This spec generalizes that into a Jenkins-inspired model: the engine requests capacity matching a **label expression**, and pluggable **pools** decide how that capacity materializes -- a local fork, a worker launched by the user in a terminal (`flow worker`), a remote host acting as a provider, or a cloud. Provisioning, assignment, and retention become separate pluggable strategies, each with a built-in default.

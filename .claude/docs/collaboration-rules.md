# Collaboration Rules

## Proposals must include pros/cons/recommendation

Every time a proposal or option is presented to the user, it MUST include:
- **Pros** — concrete advantages
- **Cons** — concrete drawbacks
- **Recommendation** — a clear stance

This applies to: architecture decisions, schema proposals, tool choices, naming decisions, any choice with trade-offs.

The user has repeated this instruction multiple times across sessions. No exceptions.

## Manual Testing Scenarios

### Scenario 1: Single Client with Reconnection

**Setup:**
1. Start backend: `npm run dev:backend`
2. Start frontend: `npm run dev:frontend`
3. Enable React StrictMode (if not already enabled)

**Test Steps:**
1. Open browser to `http://localhost:5173`
2. Open DevTools → Network → Filter by "sse"
3. Watch for SSE connection
4. Open DevTools → Console
5. Watch for connection messages

**Expected Backend Logs:**
```
[Auth] Connection authenticated: connId=..., user=dev-user-no-auth, transport=sse
[SSE] Connection ... connected (user=dev-user-no-auth, total=1)
[Subscription] Connection ... subscribed to b2f:worker:updated
```

**With StrictMode (immediate reconnect):**
```
[SSE] Replacing existing connection ... (rapid reconnect detected)
[SSE] Closed orphaned connection stream
[Auth] Connection reconnected: connId=..., preserved 1 subscriptions
[SSE] Connection ... connected (user=dev-user-no-auth, total=1)
```

### Scenario 2: Multi-Client Event Broadcasting

**Setup:**
1. Start backend: `npm run dev:backend`
2. Start frontend: `npm run dev:frontend`

**Test Steps:**
1. Open Chrome → `http://localhost:5173` (Frontend A)
2. Open Firefox → `http://localhost:5173` (Frontend B)
3. Both should connect via SSE
4. In Frontend A: Update a worker (change name, trigger update)
5. Check if Frontend B receives the event

**Expected Backend Logs:**
```
[SSE] Connection abc... connected (user=dev-user-no-auth, total=1)
[SSE] Connection def... connected (user=dev-user-no-auth, total=2)
[Subscription] Connection abc... subscribed to b2f:worker:updated
[Subscription] Connection def... subscribed to b2f:worker:updated
[EventBroadcaster] Broadcasting event "b2f:worker:updated" (excluding connId: abc...)
[EventBroadcaster] Sending to 1 connections (excluded 1)
[SSE] Broadcast b2f:worker:updated: sent=1, queued=0
```

**Expected Frontend B:**
- Should receive `b2f:worker:updated` event
- UI should update with new worker data

### Scenario 3: Rapid Reconnections (StrictMode)

**Setup:**
1. Ensure React StrictMode is enabled
2. Start backend with verbose logging: `npm run dev:backend`
3. Start frontend: `npm run dev:frontend`

**Test Steps:**
1. Open browser to `http://localhost:5173`
2. Watch backend logs carefully
3. Refresh page multiple times rapidly
4. Check for memory leaks (backend should not accumulate connections)

**Expected Backend Behavior:**
- Each refresh should close old connection and open new one
- Connection count should stay at 1
- Subscriptions should be preserved
- No orphaned connections

**Watch For:**
```
[SSE] Replacing existing connection ... (rapid reconnect detected)
[SSE] Closed orphaned connection stream
[Auth] Connection reconnected: preserved X subscriptions
```

## Debugging Tips

### Check Active Connections
In backend logs, look for:
```
[SSE] Connection ... connected (user=..., total=X)
[SSE] Connection ... disconnected (user=..., total=X)
```
The `total` count shows active SSE connections.

### Check Subscriptions
Look for:
```
[Subscription] Connection ... subscribed to <event> (no filters)
[Subscription] Connection ... subscribed to <event> with filters: {...}
```

### Check Broadcast Delivery
When Frontend A triggers an update:
```
[EventBroadcaster] Broadcasting event "b2f:worker:updated" (excluding connId: ...)
[EventBroadcaster] Sending to X connections (excluded 1)
[SSE] Broadcast b2f:worker:updated: sent=X, queued=0
```

If `sent=0`, it means no other clients are connected or subscribed.

### Common Issues

**Issue: "Sending to 0 connections"**
- Check if Frontend B is actually connected (look for connection logs)
- Check if Frontend B subscribed to the event
- Check if subscriptions were lost on reconnection (should NOT happen with fix)

**Issue: Frontend doesn't receive events**
- Check browser console for connection errors
- Check if SSE connection is active in DevTools → Network
- Check if subscription was sent successfully
- Verify event name matches on both sides

**Issue: Memory leak / increasing connection count**
- Old fix would cause this
- New fix should prevent this by closing orphaned streams
- If still happening, check logs for orphaned connection cleanup

## Success Criteria

After implementing the fixes, you should observe:

1. **Subscriptions Preserved:**
   - Backend logs show "preserved X subscriptions" on reconnection
   - Frontend doesn't need to re-subscribe after reconnection

2. **No "Sending to 0 connections":**
   - When Frontend A broadcasts, Frontend B receives it
   - Backend logs show "Sending to X connections" where X > 0

3. **Clean Connection Lifecycle:**
   - Old connections are properly closed
   - No accumulation of connections
   - Connection count accurate (matches active browsers)

4. **React StrictMode Works:**
   - Frontend can use StrictMode without issues
   - Reconnections are seamless
   - No errors in console

## Performance Monitoring

### Memory Usage
```bash
# Monitor Node.js memory
node --inspect packages/web-backend/dist/index.js
# Open chrome://inspect
```

Watch for:
- Stable memory usage (no continuous growth)
- Proper cleanup of SSE streams
- No accumulation of event listeners

### Connection Count
Backend should maintain accurate connection count:
- 1 browser = 1 SSE connection
- 2 browsers = 2 SSE connections
- Closing browser should decrement count

### Response Time
SSE events should be delivered quickly:
- Frontend A triggers update
- Frontend B receives event within 100ms
- No noticeable delay
